# 网站作用

Pages Hub 是一个**只做索引、不做镜像**的导航站。它把工作区里所有通过 GitHub Pages 部署的在线站点集中到一处，并维护「在线地址 → 部署仓库 → 源码仓库」的完整链路。

## 1. 统一入口，降低查找成本

每新增一个教程或演示项目，通常都会多出一个 Pages 地址。时间一长，地址散落在聊天记录、README 和浏览器书签里，很难快速找到。

Pages Hub 提供：

- **统一列表**：所有站点按分类展示，支持关键词、分类、状态三种筛选。
- **直接跳转**：在线站点、源码仓库、部署仓库三个链接并排呈现。
- **静态清单**：[全部项目](/projects) 由脚本生成，即使不依赖浏览器端脚本也能完整浏览，便于搜索与分享。

## 2. 源码可追溯，区分公开与私有

同一个项目的源码仓库和部署仓库经常不是同一个：

- 有的项目采用「私有源码仓 + 公开部署仓」的双仓库模式；
- 有的项目直接把构建产物推到 `gh-pages` 分支；
- 有的项目由 GitHub Actions 在工作流中构建并发布，部署仓只保存产物。

Pages Hub 明确列出这三类关系，并对私有源码仓库加上「源码私有」标记，避免访问者误以为链接失效。

## 3. 部署健康度可见

站点地址不是写一次就永远有效：仓库可能改名、Pages 可能被关闭、构建可能失败。

同步脚本会对每个在线地址发起探测，并记录 HTTP 状态：

- **在线**：返回 2xx/3xx；
- **异常**：返回 4xx/5xx 或请求超时；
- **未知**：尚未完成探测。

打开页面后，浏览器还会每 5 分钟重新校准一次可达性，因此不需要等到下一次部署才能发现掉线。

## 4. 变更可感知

每个项目会展示部署仓库的最近更新时间。结合每次推送触发的同步，可以快速判断：

- 某个站点是否长期没有更新；
- 某个项目是否刚刚重新部署；
- 源码仓库与部署仓库的更新节奏是否一致。

## 5. 作品地图与知识地图

分类维度本身也是一张知识地图。按「前端基础与进阶 / 框架与生态 / 工程化与运维 / 源码与原理 / 可视化与组件 / 架构与实战 / 全栈与 IoT / AI 与职业」浏览，可以直观看到现有内容体系的覆盖范围与空白。

## 边界与约定

- **不复制内容**：本站只保存链接和元信息，教程正文仍在各自站点。
- **不暴露私有内容**：私有源码仓库只展示仓库地址与「私有」标记，不抓取任何代码或文档内容。
- **不保证实时**：数据以最近一次构建为准；页面内校准也只反映当前网络下的可达性，不代表 CDN 边缘节点的绝对状态。
- **不替代监控**：如果需要告警，应在 CI 或独立监控系统中实现，本站定位是人工查看的导航面板。

## 适合谁

- 需要快速找到某个在线文档或演示站的自己；
- 想把作品集中展示给面试官、同事或朋友的开发者；
- 需要确认「这个站点对应哪个仓库、最近有没有更新」的维护者。
